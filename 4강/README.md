# 그르르AI — 나만의 AI 에이전트 만들기 · 4강

이 폴더는 그르르AI 채널 실습편 4강용 자료입니다.
1·2강에서 만든 에이전트(정체성 + 텔레그램 연결 + 스케줄러)에 **어디서든 접속할 수 있는 원격
경로**와 **텔레그램 미니앱으로 직접 조작하는 화면**을 붙여봅니다.

⚠️ **아직 촬영 전이라 실제 코드는 없습니다.** 1·2강과 달리 이번 강의도 3강과 마찬가지로 완성된
스크립트를 복사해서 쓰는 대신, **촬영 중에 에이전트에게 직접 프롬프트로 만들어달라고 하는 과정
자체가 콘텐츠**입니다 — "나만의 에이전트" 시리즈 취지상, 사전에 만들어둔 코드를 재생하는 게
아니라 실제 사용자가 에이전트에게 말을 걸어가며 눈앞에서 화면을 함께 완성해가는 걸 보여주기
위해서입니다. 아래 내용은 브레인스토밍으로 미리 정한 설계(특히 미니앱이 읽고 쓸 데이터
스키마)와 사전 준비물을 미리 공유하는 것이고, 실제 코드와 최종 README는 촬영·편집이 끝나는
대로 이 폴더에 채워집니다.

## 이번 강의에서 다루는 것

- **테일스케일(Tailscale) + Termius 원격 접속** — 집/회사 컴퓨터에서 돌아가는 에이전트에게,
  밖에서도 터미널로 직접 붙어서 상태를 보고 tmux 세션에 다시 attach할 수 있게 만듭니다.
- **텔레그램 미니앱(Web App) 2개** — 1·2강에서 이미 연결해둔 텔레그램 봇의 메뉴 버튼/인라인
  버튼으로 웹페이지를 띄우는 기능을 씁니다.
  - **① 음악 추천 화면 (정적)** — 오늘의 추천곡을 카드로 보여주고, 버튼을 누르면 유튜브/멜론
    같은 외부 링크로 이동만 합니다. 화면 자체엔 상태가 없고, 매번 에이전트가 새로 만들어
    띄우는 형태입니다.
  - **② 대시보드 + 투두 화면 (인터랙션)** — 화면에서 체크박스를 누르거나 항목을 추가하면, 그
    조작이 로컬 md 파일 하나(아래 스키마 참고)에 실제로 반영됩니다. md 파일이 화면의
    "데이터소스"이자 "저장소" 역할을 겸합니다 — 별도 DB 없이 지금까지 이 시리즈가 계속
    써온 "정보는 파일 하나에" 원칙을 미니앱까지 그대로 끌고 옵니다.
- **차별점**: 1·2강까지는 "텔레그램으로 대화"가 유일한 인터페이스였는데, 4강부터는 텔레그램
  안에서 실제로 누르고 체크하는 **화면**이 생기고, 그 화면이 md 파일을 통해 에이전트가 읽고
  쓰는 데이터와 **양방향으로** 연결됩니다.

## 사전 준비물

1·2강에서 만든 것을 그대로 이어서 씁니다 — **새 프로젝트가 아닙니다.**

- 1강에서 만든 `my-agent` 프로젝트 (정체성 md 파일들 + 6가지 훅 + 텔레그램 봇/Channels 연동)
- 2강에서 붙인 tmux 세션 + `scheduler_daemon.py` (원격에서 다시 attach할 대상이 바로 이 세션)
- 테일스케일 계정 (무료 플랜으로 충분) — 에이전트가 돌아가는 컴퓨터와, 밖에서 접속할 폰/노트북
  양쪽에 설치해서 같은 tailnet에 묶어둡니다.
- Termius 앱 (모바일/데스크톱) — 테일스케일로 연결된 IP로 SSH 접속해서 터미널을 쓰기 위한
  클라이언트입니다.
- 스마트폰 (텔레그램 미니앱은 모바일 텔레그램 앱에서 확인하는 게 기본 시연 환경입니다 — 데스크톱
  텔레그램에서도 뜨지만, "밖에서 폰으로 내 에이전트를 조작한다"는 그림이 이번 강의의 핵심이라
  폰 화면으로 시연합니다.)

새로 필요한 계정/설치는 이 넷뿐이고, 나머지(텔레그램 봇, Claude Code, tmux)는 1·2강 것을
그대로 재사용합니다.

## 미니앱 데이터 설계 (초안 — 촬영 중 그대로 쓰거나 대화하며 바뀔 수 있음)

②번 대시보드+투두 미니앱이 읽고 쓸 데이터소스는 **`todos.md` 하나**로 정합니다. 이 시리즈가
지금까지 정체성(md)·기억(md)·스케줄(파이썬 딕셔너리) 전부 "사람도 읽을 수 있는 평문 파일"을
고집해온 것과 같은 이유입니다 — 미니앱이 고장 나거나 아직 안 만들어졌어도, 에이전트가 그냥
이 파일을 Read/Edit하는 것만으로도 투두 기능이 대화로 동작해야 합니다. 미니앱은 "이 파일을
누르고 체크하는 것만으로 조작할 수 있게 해주는 화면"일 뿐, 진실의 원천(source of truth)은
항상 이 md 파일입니다.

### `todos.md` 형식 초안

프론트매터(YAML)로 메타데이터를, 본문은 마크다운 체크박스 리스트로 항목을 표현합니다 —
사람이 에디터로 직접 열어도 그대로 읽고 고칠 수 있어야 한다는 원칙을 지킵니다.

```markdown
---
updated: 2026-08-19T21:40:00+09:00
---

## 오늘

- [ ] 장보기 #집안일 !중간
- [x] 이메일 회신 #업무 !높음 @2026-08-19
- [ ] 운동 30분 #건강

## 다음

- [ ] 병원 예약 #건강 !낮음
```

필드 표기 규칙(초안):

| 표기 | 의미 | 예시 |
|---|---|---|
| `- [ ]` / `- [x]` | 미완료 / 완료 | 체크박스 클릭 시 미니앱이 이 문자를 토글 |
| `#태그` | 카테고리 | `#집안일`, `#업무`, `#건강` |
| `!우선순위` | 우선순위 | `!높음` / `!중간` / `!낮음` (생략 가능, 기본값 `중간`) |
| `@완료일` | 완료 처리된 시각 (YYYY-MM-DD) | 체크 시 미니앱/에이전트가 자동으로 붙임, 미체크로 되돌리면 제거 |
| `## 섹션명` | 그룹 헤더 | "오늘" / "다음"처럼 자유 텍스트, 미니앱은 이 헤더 단위로 컬럼/탭을 나눔 |

**왜 프론트매터 + 체크박스 조합인가:**
- 프론트매터의 `updated`는 미니앱이 폴링할 때 "파일이 마지막으로 언제 바뀌었는지"를 빠르게
  확인하는 용도입니다(2강의 `watch-hash.json` 패턴과 같은 목적 — 매번 전체 내용을 비교하는
  대신 타임스탬프 한 줄만 먼저 봅니다).
- 체크박스는 옵시디언·노션·GitHub 마크다운 등 어디서 열어도 그대로 인식되는 가장 범용적인
  "완료 상태" 표기라 별도 파서 없이도 사람이 바로 읽을 수 있습니다.
- 태그(`#`)·우선순위(`!`)·완료일(`@`)은 정규식 하나로 뽑아낼 수 있는 수준의 가벼운 표기만
  씁니다 — 촬영 중 실제 파서를 즉석에서 만들어야 하므로, 문법이 복잡해지면 그 자체가
  실습 난이도를 불필요하게 올립니다.

### read/write 뼈대 설계 (개념만 — 실제 엔드포인트/코드는 촬영 중 제작)

미니앱(웹페이지)이 `todos.md`를 직접 파일시스템으로 열 수는 없으므로(브라우저 샌드박스),
중간에 작고 얇은 로컬 서버가 파일을 대신 읽고 써주는 역할을 해야 한다는 것까지만 이번
문서에서 미리 정해둡니다 — 실제 구현(포트 번호, 프레임워크 선택, 인증 방식 등)은 촬영 중
결정합니다.

- **읽기 방향**: 미니앱이 뜰 때(또는 주기적으로) `todos.md`를 파싱한 결과(섹션별 항목 배열)를
  받아와 화면에 그립니다.
- **쓰기 방향**: 사용자가 체크박스를 누르거나 새 항목을 추가하면, 그 변경 하나를 서버에
  전달해서 `todos.md`의 해당 줄만 정확히 고쳐 씁니다(파일 전체를 덮어쓰지 않고, 2강에서
  "diff 방식으로 새 행을 감지해야 한다"고 배운 것과 같은 이유로 — 부분 수정이 안전합니다).
- **동시 편집 충돌**: 미니앱에서 고치는 동시에 사람이 직접 에디터로 `todos.md`를 열어 고치고
  있을 수도 있다는 걸 전제로, "마지막에 쓴 쪽이 이긴다"보다 더 안전한 처리(예: 프론트매터의
  `updated`를 낙관적 잠금처럼 쓰기)가 필요한지도 촬영 중 판단할 지점입니다.

이 구조를 미리 문서로만 남겨두는 이유는, 촬영 시작 시점에 "무엇을 만들어야 하는지"에 대한
합의는 있되 "어떻게 만들지"는 여전히 열려 있어야 하기 때문입니다 — 3강이 브레인스토밍
설계와 겪었던 함정만 미리 공개하고 실제 코드는 촬영으로 넘긴 것과 같은 원칙입니다.

## ① 음악 추천 화면은 왜 정적인가

②번과 달리 ①번(음악 추천)은 md 데이터소스가 없고, 상태도 저장하지 않습니다. 에이전트가 매번
"오늘의 추천곡"을 새로 판단해서 그 내용으로 미니앱 화면을 새로 만들어 띄우고, 사용자는 그
화면의 버튼을 눌러 외부 링크(유튜브 등)로 나가는 것으로 끝입니다 — 이 시리즈에서 "판단이
필요 없는 반복 작업은 파이썬/화면으로, 판단이 필요한 부분만 에이전트가"라는 원칙(2강 후반부
참고)을, 정반대 방향에서 보여주는 예시이기도 합니다: 여기서는 오히려 "판단(오늘 뭘
추천할지)은 에이전트가 하고, 그 결과를 예쁘게 보여주는 화면만 정적으로 찍어낸다"는 조합입니다.
②번(대시보드+투두)과 나란히 두면 "상태 없는 화면"과 "상태 있는 화면"의 차이가 뚜렷하게
대비됩니다 — 촬영 의도이기도 합니다.

## 실습 vs 시연

- **직접 따라할 수 있는 부분**: 테일스케일 설치·tailnet 연결, Termius로 SSH 접속 — 진입장벽이
  낮아서 시청자 본인 환경으로 그대로 실습 가능합니다.
- **함께 만들어가는 부분**: 미니앱 2개의 실제 코드 — 위에서 밝혔듯 촬영 중 라이브로
  완성합니다. 시청자는 완성된 코드를 받는 대신, 완성되는 "과정"을 보고 자기 에이전트에도
  같은 방식으로 요청해서 직접 만들어보게 됩니다.
